## 使用

沿用现场原 API 地址和原 token。文件顶部 `API_URL` 默认沿用参考工程地址，也可用 `OPENWAM_API_URL` 覆盖；`API_TOKEN` 从原 `OPENWAM_API_TOKEN` 环境变量读取，不在公开脚本中写入凭证。

```bash
# 原机械臂 ROS / calib Python 环境，且已有 OPENWAM_API_TOKEN
python3 infer_openwam_clean.py
```

每批只询问：Reset（1/0）、执行几轮（0退出）、任务编号（1–8）。选定后自动执行该批所有推理轮次；没有 EXECUTE 确认、逐轮回车或逐轮询问复位。任务严格采用用户给出的8条英文。若跳过首次复位，顶部 `INITIAL_GRIPPER` 必须对应当前开合（默认1为开）；后续仍是命令估计，不伪称实测抓取反馈。

## 已落实的修改

1. 复位使用 place_sphere/slot0016/Clean/frame0 的真实训练初始 TCP：xyz `[.611998618,-.008745952,.170624807]` m；旋转由原训练6D列向量还原。复位至少3秒，并按关节速度上限延长。
2. 明确机械臂基座为 `mk1000_fr3_link0`，所有 IK 请求也明确使用它。FK 即使来自带移动底盘偏移的完整 URDF，也先消掉 root→link0，再用于模型状态，避免同名 base_link 混用。
3. 从实际加载的 URDF 推导 link8→hand_tcp，不再手抄105.4mm/45°变换。复位及预测动作均走 `inverse(T_MODEL_FROM_ARM_BASE) @ T_model_tcp @ inverse(T_link8_tcp)`。默认模型base与FR3 link0轴系对应，外部标定若有不同，修改顶部这个显式矩阵。
4. 按用户最新要求，`CHUNK_STEPS=32`；可改16。先对整个前缀求IK，再一次发送一条包含当前点和32个目标点的 JointTrajectory。累计时间戳名义间隔 `.5s`（用户反馈抖动后由初版 `.05s` 放慢），关节速度超过 `.5rad/s` 时延长段时长；不是每点1秒的循环。
5. 夹爪事件在对应段开始时发送，与机械臂轨迹同一时轴，不再每点等待1.2秒后才发送。
6. IK失败报错，不回退当前关节角；同时验证IK/FK的位置和旋转，到达后也检查TCP位置与角度。IK启用MoveIt碰撞检查；这不等于整个连续轨迹的碰撞验收已完成。
7. 关节反馈改为持续订阅；IK等待使用后台executor完成回调，避免父类在两个线程中重复spin节点。保留必要的响应格式、缺失/过期关节反馈、50mm预测段及1rad关节跳变检查。
8. Ctrl+C/SIGTERM或执行异常退出时，在关节反馈正常的条件下发送当前关节保持轨迹，覆盖已排队的前缀；随后退出ROS。强制kill/断网/反馈丢失不能用软件保持代替硬件停止。
