最近500微步（41,775–42,274），Action为0.000217903→0.000227795（+4.540%），EA+0.052%、Relation+5.821%、Plan−3.249%。这些小窗口存在波动，不能选其中一段作为成功率提升或显著退化的证明。

辅助头仍在接受监督，当前训练loss没有明显全面崩塌；但EA总项几乎不变，也不能证明关系泛化可靠。仍需固定输入的Ground峰值命中、Contact/Moving F1、方向cos和最终闭环。

| Block7 | −0.00288391 | −0.00283813 | −1.59% |
| Block15 | −0.00285339 | −0.00283813 | −0.53% |

Read alpha：Block7两组均0.0673828，Block15均0.119141；Block23原0.0334473、heads-only0.0332031（约−0.73%）。

这次没有观察到“detach后gate明显增强”。当前记录是BF16可见标量，曲线呈量化台阶；长期显示相同不能证明底层FP32优化器状态没变。beta符号和大小都不等于实际write residual/hidden比，也不能据此判断条件更有用或无用。

## 4. Adapter权重现在能看到哪些

新分支按原`save_steps=4000`运行，42k不是保存点，最终42960才会保存新权重。**当前没有heads-only的中间adapter checkpoint，不能把40k初始文件当成42.2k的实时参数，也没有读取运行中GPU内存来伪造这个比较。** Gate来自日志，adapter矩阵来自已完成保存的safetensors。

已在CPU选择性读取初始40k和原训练最终42960的全部Sidecar tensors，检查形状/有限性及文件完整性。相对L2变化定义为 `||W42960−W40000|| / ||W40000||`，不是单纯比较两个范数之差。

| 映射权重，原训练40k→42960 | Block7 | Block15 | Block23 |
|---|---:|---:|---:|
| Read projector：3072→512 | 0.370% | 0.363% | 0.436% |
| Write query：1024→512 | 0.054% | 0.104% | 0.134% |
| Write output：512→1024 | 0.163% | 0.172% | 0.160% |

例如Block7 Read投影L2范数15.154440→15.154321，两个范数几乎不变，但实际相对L2差0.370%，约53.8%的BF16元素已变化。Write output约20.1%的元素变化，相对L2差0.163%。因此不能只看范数接近就说adapter没训练。

上述表格**仅描述原训练的变化**，不声称heads-only adapter也具有同样变化。原run在40k后学习率已经接近1e-6，整体权重变化不大属当前观测，不能由此否定更早阶段的路由策略。
