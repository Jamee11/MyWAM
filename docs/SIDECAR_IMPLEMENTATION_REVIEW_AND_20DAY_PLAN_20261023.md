# Sidecar 当前实现、问题判断与 20 天论文计划

记录时间：2026-10-23 UTC。训练日志快照：02:41:04 UTC。

本轮只审查现有实现、实验产物和训练日志，整理研究决策；不修改模型、训练、数据或部署代码，不启动新实验，不干预当前作业。用户已确认：有可控单臂真机，相机和控制接口已跑通。

## 1. 核心判断

**方向仍然值得继续，但目前最缺的是“关系监督带来了可归因的控制收益”，不是更多网络容量。** 已有结果支持 Sidecar 能从 WAM 特征中读出关系与未来运动信号；旧模型直接写回很弱，尚无稳定闭环增益的证据。新的 warmup 已改变 gate 学习行为，不能继续用旧 42960 的诊断直接判断新模型。

建议将论文核心问题收敛为：**只在训练时使用仿真关系监督，能否让预训练 WAM 在外观、目标物及场景变化下保持更可靠的控制，并减少目标真机的数据需求？** 写回范数、辅助预测精度和梯度比例用于解释这个问题，不能替代成功率和数据效率。

最优先的行动顺序：保留当前训练作为完整对照 → 补匹配 Vanilla → 检验新 warmup 的动作收益与实际写回 → 只有必要时选一种最小调整 → 配对闭环和单臂真机。不要同时重做 Transformer、Gate、辅助目标与训练阶段。

## 3. 实现与初衷之间，哪些一致、哪些需要收紧

### 3.1 当前 Sidecar 已经是 Transformer 式结构

现有 Sidecar 约 **24.29M 参数**，三个独立 stage，分别接在 zero-based Block 7、15、23 后。宽度 512、8 头；每阶段包含视觉 cross-attention Read、token self-attention Refine、FFN，以及写回 Action hidden 的 cross-attention。15 个 token 分为 4 个 Ground、4 个 Relation、1 个 Summary、6 个 Plan。

它不是几个很小的辅助 MLP。仅辅助 heads 约 0.53M，占 Sidecar 约 2.19%；主要参数已经用于表征和条件融合。当前没有证据表明增加 Transformer 深度是最有效的修复。

实际前向关系是：

```text
当前 RGB / 文本 / proprio
         ↓
WAM 当前帧多层 hidden → Sidecar Read / Refine → 关系 latent tokens
                                               ├→ 辅助 heads → 与仿真 GT 算 loss
                                               └→ Write → Action hidden → 动作生成
WAM 原始 world–action 主路径始终保留
```

重要含义：**写回使用 latent tokens，未直接使用预测出来的 contact、goal proximity 或 plan 数值。** 辅助头能预测正确，不能保证 Write 使用了这些语义；Action 也可以通过原主路径完成任务。

### 3.2 当前具体监督没有覆盖全部设想

| 想要的能力 | 当前实际实现 | 尚不能声称的内容 |
| --- | --- | --- |
| 物体感知 | 固定双臂 Object/Goal 角色；辅助 grounding 热图、presence、track-valid | 不是通用多物体场景图；辅助热图也不直接等于 Read 的注意力 |
| 关系理解 | near、gripper–object contact、goal proximity | 标签有相对 XYZ，但当前 loss 不回归完整相对 XYZ；高 F1 不代表精细几何控制能力 |
| Task progress | 一个无专门进度 GT 的 Summary token；另有目标接近程度 | **没有显式受监督的 task progress**；靠近目标不等于任务完成阶段 |
| Future plan | 8/16/32 步 EEF/Object 自身局部单位位移方向与 moving | 不是完整动作计划；缺位移幅度、旋转与夹爪事件监督 |
| 时间动态 | 每次 forward 重新初始化 tokens，读取当前帧的多层 WAM 特征预测未来信号 | 没有跨控制步记忆，也没有直接读取 WAM 预测未来帧；不能写成已建成显式未来轨迹推理器 |

因此，当前更准确的描述是：**通过仿真特权监督塑造关系表征，再把这些表征作为 WAM 动作生成的可学习条件。** 推理阶段没有新增 oracle 信息，而是尝试改变同一观测中的信息组织和利用方式。

部署输入约束明确拒绝 EA GT；训练标签单独进入 loss。现有代码没有显示物体 GT 被直接喂入策略推理。这个设计有利于真机部署，但还不构成 sim-to-real 有效性的证明。

实现依据：[Sidecar 模块](../openwam/model/modules/relational_sidecar.py)、[架构与 loss 路由](../openwam/model/architectures/dual_system/relational_sidecar.py)、[标签构造](../openwam/dataloader/ea_rsig_lite.py)、[关系/计划损失](../openwam/model/modules/ea_rsig_v3.py)。

## 4. 问题更可能出在哪里

### 4.1 “随机 Sidecar 一接入就破坏预训练”仍是假设

当前初始化是 β=0、输出投影正常初始化。第一次前向的 Action 写回残差严格为零，不存在两个零初始化导致分支永远无法学习的问题。

但是，**EA loss 可以经 Read 和 Grounding features 直接更新 Video backbone，这条路径不经过 Write gate。** 所以必须区分三件事：

1. 随机写回在学习初期干扰动作；
2. 随机辅助预测目标通过反向传播改变预训练视觉表征；
3. 主干已经很强，能快速拟合 Action，而新 Sidecar 主要学会辅助预测，动作没有形成利用它的必要性。

目前第 2、3 项都是值得检验的机制解释，尚无严格因果结论。旧模型 gate 很小也可能是优化、数值尺度、信息冗余或共同适应的结果，不能直接解释成“模型主动排斥 Sidecar”。

### 4.2 旧梯度结果意味着“目标分配不平衡”，不意味着必须让梯度一比一

当前训练目标为：

\[
L=L_{action}+L_{video}+\lambda_{EA}
\left(0.025L_{ground}+0.01L_{relation}+0.05L_{plan}+0.1L_{deep}\right).
\]

当前新配置 λEA=0.5，Deep 是既有中间层加权监督。

- Action 和 Video 都能通过 Write 训练 Sidecar；不能只分析 Action/EA 两项。
- EA 能训练 Read/Refine/Plan 和 heads，但受首帧隔离与计算图限制，不直接训练 Write 的 β/输出投影。
- 小 β 会缩小传向 Write 上游表征的 Action 梯度，因而旧梯度比例可能同时是弱写回的结果和继续弱耦合的原因。
- 降低整个 Sidecar 的学习率会同时影响多种目标，不能解决它们在共享参数上的相对主导关系；EA 权重减半也不能消除几万倍差距。
- 梯度范数、梯度方向、Adam 动量与真实参数更新是不同量。辅助 CE 还有目标熵下界，不能比较 loss 标量大小就宣布主导关系。

需要关注的是：**共享表征是否在不断学会“更好回答辅助问题”，却没有变成更有用的控制条件。** 不需要预先规定某个梯度比例或写回比例是正确答案。

### 4.3 关系预测准确，不代表它提供了主干缺少的东西

现有诊断已超过简单任务常量先验，但尚未排除依靠 proprio、任务阶段和常见动作模板的捷径。每域仅 3 条新专家轨迹，接触诊断也不覆盖敲击器具与目标的碰撞、松手等所有关键事件。

更重要的是，原 WAM 可能已隐式包含同样的信息。Sidecar 的价值应体现为：少数据时更有效、外观改变时更稳、关键物体关系变化时动作更正确。仅增加辅助预测精度不足以建立论文贡献。

## 5. 两种 warmup 的比较与最新训练发现

### 5.1 当前方案更符合“先学会被 WAM 使用”

| 前 2000 次 optimizer updates | 旧隔离 warmup | 当前 WAM 延迟更新 warmup |
| --- | --- | --- |
| 读取主干 hidden | 是，读取输入 detach | 是，正常计算图 |
| 写回 Action hidden | 关闭 | 开启 |
| Action/Video 训练 Write | 否 | 是 |
| EA 训练 Sidecar | 是 | 是 |
| WAM 参数更新 | 是，原 FM 训练 | 否，完整反向与裁剪后在 Adam step 前跳过 |
| 2K 后 | 联合训练，Write 才开始学习 | 已预热的完整读写继续运行，WAM 开始更新 |

旧方案主要预热关系预测；当前方案还让 Sidecar 提前适配固定主干的动作生成过程。因此，**当前方案在机制上更贴近本项目目标**，但优劣仍需同条件闭环验证。

不建议追加“冻结 Sidecar、只训练 WAM”的第三阶段：它让双方轮流追赶变化的接口，又增加一个训练阶段和混杂变量。若需要缓和切换，优先考虑 WAM 学习率平滑恢复，而 Sidecar 继续正常训练。

### 5.2 新训练已经越过 2K，gate 的行为发生了明显变化

2026-10-23 02:41 UTC 快照：microstep **6926**、optimizer update **3463**；warmup 标记为 0，已进入联合训练，最新 loss 有限。已保存 `checkpoint_step_4000.safetensors` 及对应 `accel_state_step_4000`，后者计数为 optimizer=2000。

最新 β 约为 **−0.01575 / −0.02197 / −0.02100**。新方案在第 1999 次更新时约为 −0.0273/−0.0393/−0.0374，而旧 joint 同时刻约为 +0.000183/+0.000301/−0.000186。说明新训练 recipe 下 gate 的学习行为确实变化了。

**这还不是实际写回更有效的证据。** Write projection、token 与 hidden 尺度也在变；解冻后 β 绝对值正在回落，不能仅据此判断是负面压制。当前日志没有实际 write-r，旧模型的 1e-6 残差结论不能直接套在新模型上。

另外，新版相对旧 joint 同时改了 Sidecar LR（1e-4→5e-5）和 EA scale（1→0.5），不能将全部变化归因于 warmup；两种新 warmup 的配置比较更接近单变量。

### 5.3 本次新发现：恢复 WAM 更新时有短暂尖峰

全局 LR scheduler 在前 2K 仍推进，WAM 第一次更新时 Adam 状态从零开始，但学习率已经约 **9.95e-5**，接近峰值。

| 更新区间 | Action loss 均值 | 梯度 norm 最大值 | norm>1 的更新比例 |
| --- | ---: | ---: | ---: |
| 1900–1999 | 0.015684 | 0.929 | 0% |
| 2000–2100 | 0.012470 | 12.558 | 13.86% |
| 3300–3400 | 0.002129 | 0.351 | 0% |

第一次 WAM 更新前 Action loss 约 0.01543，后续微步短暂升至 0.12550/0.14227，随后恢复下降。**这是已观察到的边界瞬变，不是持续发散；目前未证明它损害最终成功率。** 因此不应中断当前训练，但它为“WAM 解冻时短 LR ramp”提供了比泛泛猜测更直接的候选依据。

另一个保留项：WAM 在前 2K 虽不更新，却参与全局梯度裁剪，会影响 Sidecar 被裁剪的尺度；这符合当前实现，不能等同于只对 Sidecar 梯度裁剪。先记录，不与其他优化改动同时修改。

机器可读证据：[训练日志快照](evidence/sidecar_review_20261023/training_log_snapshot.json)。这是日志统计，不是新 GPU 诊断、完整模型重载或闭环效果验证。

## 6. 容易漏掉、但可能影响实验结论的问题

1. **腕部相机近裁剪面不一致。** 训练采集为 0.02m，当前官方评估为 0.1m；RGB/尺寸/拼图链路已检查，不代表可见内容一致。既有 near A/B 尚未完成，客户端导入错误属于基础设施问题，不能当作效果结果。应补完已有小对照，主成绩继续保留官方配置，不能改协议后混报提升。[图像审计](ROBOTWIN_TRAIN_EVAL_IMAGE_ALIGNMENT_20261022.md)、[near 对照](ROBOTWIN_WRIST_NEAR_AB_20261022.md)。
2. **动作格式一致不等于执行一致。** RoboTwin 标签是专家实际到达的未来 EEF，部署再将预测当作规划目标；真实专家标签回放、跟踪与时序尚缺完整验证。ManiSkill 已有原 delta/绝对命令 12 次专家回放通过。离线动作误差不是实际 TCP 跟踪误差。[EEF 审计](ROBOTWIN_EEF_TRAIN_EVAL_ALIGNMENT_20261020.md)。
3. **强一点的 Sidecar 需要重新检查推理加速。** 相同 cache 阈值不保证不同模型跳过同样的计算。新 checkpoint 应复用现有编译数值检查，并在少量固定输入上检查 cache 对动作的影响；不要把旧弱写回 checkpoint 的验证直接外推。
4. **角色切换与精细交互监督不足。** Plan 在角色 ID 不一致时会 mask，避免错配但减少了切换附近监督；方向/moving 与粗 near 对精细放置、旋转、释放仍不充分。这是后续几何监督候选的依据，不是现阶段已证明的主要失败原因。
5. **Clean-only+ColorJitter 不等于全面 OOD 训练。** 它不自动覆盖几何、遮挡、动力学或相机差异。若加入 Randomized 训练，必须作为另一协议，不能继续称原 Clean2Random 对照。
6. **高成功率任务有天花板。** ManiSkill 已有 96% baseline，应额外用预先固定的外观/干扰物/物体位置变化衡量鲁棒性；不能事后只选改善任务。

这些项应作为跨方案共同的协议检查；修复收益不能全记在 Sidecar 架构名下。

## 7. 提高性能的方案：按证据与成本排序

| 优先级 | 候选 | 何时值得做 | 最小比较与主要风险 |
| --- | --- | --- | --- |
| P0 | 保留当前正常读写、WAM 延迟更新方案并完成验证 | 现在 | 新 gate 已明显变化；先验证新模型，不沿用旧模型结论直接重构 |
| P0 | 匹配 Vanilla 与统一评测 | 现在，并行准备 | 是判断方法是否有收益的前提；数据、stats、增强、预算及推理要对齐 |
| P1 | **WAM 解冻 LR 短 ramp** | 需要处理已见的边界冲击时 | 同一 2K full-state 分叉，只让 WAM LR 在预设 100–500 更新内从小值渐增至原 schedule；Sidecar 正常训练。只选一个长度，不做网格扫描；可能只改善瞬态而不改善最终 SR |
| P1 | **Stage2 EA 只训练 heads** | 新模型仍呈 EA 主导且没有动作收益时 | 仅辅助 heads 的 tokens/features 输入 detach，正常 Read/Refine/Write 计算图保持；EA 不再推动共享 Sidecar/WAM，Action+Video 接管共享表征。风险是关系语义遗忘；这是待测候选，不是已实现功能 |
| P2 | Read 输入 detach | 证据指向辅助目标改变主干表征时 | 阻止经该读取路径回到 WAM 的梯度，保留 EA 对 Sidecar 的监督；也切掉 Action/Video 经 Sidecar Read 回主干的梯度，主 WAM 路径仍正常。因此不能称完全选择性的 EA→WAM 隔离，也不能解决 Sidecar 内部 EA 主导 |
| P2 | β=1、输出投影零初始化 | 新模型仍存在写回优化瓶颈时 | 新训练实验，不改已训练权重；初始残差为零，输出投影可先获梯度，上游仍需投影非零后学习。当前新 gate 已不小，暂不列第一优先 |
| P2 | 增加连续相对几何/位移幅度监督 | 失败集中于几何控制且已排除执行问题时 | 优先利用已有可靠标签加一种物理含义明确的目标；先核对 frame/validity。新增目标也可能进一步压过 Action，不与路由一起改 |
| 暂缓 | 更深 Transformer、Task Gate、Progress head、Action–Plan 新对齐损失、混合本体 midtrain | 现有证据不足以要求这些结构变化 | 同时引入会扩大实验矩阵，20 天内难以归因与完成验证 |

**建议执行决策：先保留当前 run；新 checkpoint 做一轮短验证后，只选表中的一项训练调整。** 若当前模型已经有清晰控制收益，就不为“gate 看起来还可以更大”而重启训练。若只看到边界尖峰但后续稳定，LR ramp 作为稳定性候选；若稳定期仍是 EA 主导且动作无收益，则优先 Stage2 梯度路由，而不是同时叠两项。

已有文档中的 heads-only 候选与本轮 LR ramp 解决不同问题，应分开评估。前者处理训练目标分配，后者处理主干恢复更新的瞬态。

## 8. 最小实验矩阵与决策门槛

### 8.1 不能省掉的控制组

| 组别 | 用途 |
| --- | --- |
| V：Matched Vanilla | 判断相同资源/数据条件下 Sidecar 是否有净增益 |
| EW：当前完整 Sidecar warmup | 主要方法 |
| E：训练期间保留 EA，但始终关闭 Write | 区分辅助监督改变 backbone 与推理写回本身的训练效应 |
| W：相同 Sidecar 容量与 Write，但不加 EA 监督 | 若论文主张收益来自关系监督，需要排除“只是多了 adapter”的解释；预算不足可在固定代表子集做，并明确限制 |

运行时 Full/Write-Off 仍有用，但不能替代上述训练对照。E、W 在只对 Sidecar 预热的阶段可用的训练信号不同，必须披露，不能把各组差值解释成严格可加的单一贡献。

同一总更新/数据遍历预算是主比较，同时报告 WAM 和 Sidecar 各自实际更新次数；当前 WAM 比总更新少 2K。若需要解释“效果只是少训主干”，再补匹配 WAM 更新次数的敏感性对照。旧 joint 与新 warmup 的 LR/EA 权重差异必须写明。

### 8.2 新模型只做一轮短诊断，再返回闭环

复用已有入口与固定样本，限 1–2 天，不重新开发诊断系统：

- 检查三层实际残差与加法前残差，保留 BF16 舍入影响；比较 Full/Write-Off 的 XYZ、Rotation、Gripper 误差，而非只看动作变化。
- 在固定少量任务/噪声时间上复测加权 Action/Video/EA 梯度；旧结果若已改变，就停止沿旧假设调整。只在必要时分解 Ground/Relation/Plan，loss 标量占比不能代替梯度归因。
- 固定三个已有诊断任务、双域，每条件 10 场景，共 60/模型，做配对闭环筛选；这是筛选集，不作为最终证明。
- 若要证明语义内容被使用，做一次匹配任务、阶段与尺度的 token 置换对照；保持正常预测，只替换 Write 输入。置换可能 OOD，不能把受损完全解释为正确语义的因果作用。

候选只有在动作指标与配对闭环总体支持、且关系预测没有明显崩溃时进入大预算。若结果接近或只有单任务偶然提升，保留简单方案，不追加更多参数搜索。

最终测试使用独立 seeds。按任务报告成功率、成对赢/输和置信区间；以 episode 为单位，不能将同一轨迹中的多个窗口当作独立成功样本。主结果优先完整 RoboTwin 50 任务及 ManiSkill 六任务；若时间不足只能做预先声明的代表子集，就明确范围，不能写全 benchmark 结论。

## 9. 单臂真机：现在并行，聚焦一个平台

用户已有可控机器人和可用相机/控制接口，因此不必等最后几天才开始。**优先从现有 ManiSkill 单臂分支与其 baseline/Sidecar checkpoint 对照出发。** 当前 Aloha 训练成功不等于可以直接跨本体零样本上单臂；80D 容器相同也不保证控制语义和动力学一致。

### 建议验证顺序

1. 在现有接口上核对 base/TCP frame、工具偏置、旋转约定、夹爪范围、相机输入和归一化；明确控制频率与动作重规划周期。若目标机器人不是数据中的同一本体，先把差异记入部署契约。
2. 选择 **2–3 个已有仿真语义对应的任务**，例如抓取放置、指定物体选择、目标区域放置。先验证正常场景，再固定外观/干扰物/位置变化；不要一开始扩成复杂长程任务集。
3. 在正常工作空间和小幅动作回放验证之后，先测 baseline 与现有 Sidecar，保存全部尝试与失败类型；不能只展示成功视频。评估时固定场景，交替模型次序，降低人工布置漂移。
4. 将 zero-shot 定义为 **目标真机任务上零示范、零微调**，保留正常标定与控制适配；不能将“零目标示范”扩张成预训练从未见过真实数据。
5. 若零样本不稳定，转为明确的 few-shot 曲线，例如 0/5/10 条真实示范，两方法使用完全相同的示范、训练预算与独立测试场景。5/10 是可执行的预算建议，不是预先保证足够。

真机缺 EA GT 时，不能填零标签冒充“无接触/无运动”。Few-shot 需要明确缺失监督 mask 或只优化可用 Action/Video 目标的路径；这部分不能从当前仿真 loader 自动推断为已经支持，也不在本轮实施。

在 20 天内，可信的 2–3 任务成对结果与数据效率曲线，比仓促承诺跨本体、广泛零样本泛化更有价值。如果只能证明 few-shot，就如实以 few-shot 为主结论。

当前训练近期约 6.58 秒/microstep，完整 42960 microsteps 粗算约 78.5 小时，不含启动、保存、争卡及评测。因而不适合串行跑很多个 10-epoch 变体。已有 2K full-state 支持只续训 500–1000 optimizer updates 的短对照；按当前速度约 1.8–3.7 小时，再加加载/验证。正式测试并发与墙钟时间仍应按实际资源规划，不能把这个估计当预约保证。

**决策底线：第 5 天后不再无证据叠网络；第 10 天仍没有匹配对照增益，就不要用“gate 变大”“关系 F1 高”包装成策略提升。** 此时缩小结论、保留负结果与机制分析，比继续扩范围更可靠。

## 11. 论文应该如何组织贡献

建议的主叙事是：**利用训练时仿真关系监督，建立可部署的结构化条件；通过受控预热让其与预训练动作先验协调，并验证在分布变化和少量真机数据下的控制价值。** 这目前是待完成证据链，不是已经成立的论文结论。

论文需要回答三个问题：

1. **有效吗？** 相同条件下是否优于 Vanilla，尤其在预先定义的 OOD 条件和有限示范预算下。
2. **为什么有效？** EA-only、write-without-EA、完整方法与运行时 Write-Off，能否区分辅助正则化、额外容量和语义写回。
3. **能部署吗？** 不使用物体 oracle 的真实单臂成对结果、数据预算、失败类型和延迟。

仅“加 Sidecar + 2K warmup”本身不应当作充分的新颖性。OpenWAM 已经有 world–action 信息交互；冻结预训练主干、通过初始零残差学习条件也有既有方法先例。需要把贡献落在关系监督的可验证增量与部署价值，相关工作明确引用，避免将通用训练技巧当作首创。[OpenWAM](https://arxiv.org/abs/2609.07398)、[ControlNet](https://arxiv.org/abs/2302.05543)

当前可以说：模型有关系/未来运动预测能力，旧写回贡献弱，新 warmup 已显著改变 gate 学习，ManiSkill 有初步正面控制结果。当前不能说：Randomized 鲁棒性已提高、Sidecar 控制收益已严格归因、显式任务进度已学会、零样本真机已经实现。
